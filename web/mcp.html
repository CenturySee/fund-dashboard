MCP 服务状态

服务已实现 · VPS 部署后可用

服务使用 Streamable HTTP，部署目标地址为 https://funds.imak.top/mcp。需先由维护者安装并启动服务；本页不代表线上已开通。GitHub Pages 只提供静态数据。

在支持远程 MCP 的客户端中添加服务，选择 Streamable HTTP 并填写以上地址。若维护者启用了令牌，客户端还需发送 Authorization: Bearer <令牌> 请求头。此服务未实现 OAuth 登录，需使用支持自定义请求头的客户端，或由维护者提供公开只读访问。

{
  "mcpServers": {
    "fund-dashboard": {
      "type": "http",
      "url": "https://funds.imak.top/mcp"
    }
  }
}

以上是常见配置形式，具体字段以客户端为准。本地启动时地址为 http://127.0.0.1:3100/mcp。

现在就能用：直接读取 JSON

支持 HTTP 读取的 agent 可从 llms.txt 获取机器可读说明，无需解析表格或执行页面脚本。以下链接相对于本站目录，兼容 GitHub Pages 的项目路径。

  1. 读取 data/index.json，获取指数 key。
  2. 读取 data/{key}/manifest.json，获取 latest 和 checkedAt。示例：纳指100、标普500。
  3. 读取 data/{key}/{latest}/results.json，在返回数组中筛选基金。
  4. 需要变化说明时读取同目录的 changes.md；历史日期从 manifest.dates 获取。

可以把这段指令发给 agent：

请读取此看板的 llms.txt，按其中的步骤查询最新限购信息。
分别列出纳指100和标普500可申购的基金、代码、申购状态及额度。
每个指数注明最近核查时间和最近变更日期；未知额度保留为未知。

读取时需要保留的语义

字段解释
checkedAt该指数最近成功核查时间，ISO 8601 格式；展示时可转为北京时间。缺失时表示核查时间未知。
latest最近限购变化的快照日期。连续相同快照会去重，因此可能早于核查日期。
generated文件生成时间，不能替代核查时间。
code / name基金代码保留前导零；基金名称保留份额类别。
buy_status / buyable原始申购状态与可买标记。暂停申购时，即使额度字段有数值也不能判断可以买。
daily_limit / minsg / maxsg展示额度和原始额度字符串。空值不代表零或不限额；计算前须明确单位。

这是定时更新的快照。收益、净值和评分仍对应保留的快照，不代表最近核查时已刷新。请求失败应明确报错，不应解释为“没有变化”。

MCP 查询工具

只读工具 get_latest_limits 支持 index（nasdq100 / sp500，省略查全部）、code（六位字符串）、buyable（布尔值）、offset（默认 0）和 limit（默认 30，最多 100）。

{ "index": "nasdq100", "buyable": true, "limit": 20 }

结果包含 indices、funds、total、nextOffset。nextOffset 非空时继续分页。各指数的 stale 默认表示超过 96 小时未核查，时间未知时为 null。

记录中的 effectiveBuyable 优先尊重暂停状态；statusConflict 提示状态与原始可买标记冲突。原始额度保持字符串，未知值保留。服务定义输入与输出 schema，并返回结构化结果。
